# AGENTS.md — BlatUI Semantic Registry

This repo is a **semantic component registry** for [BlatUI](https://github.com/remix-ui/blat-ui), a shadcn-style
Laravel component CLI. Every component ships as a pure semantic CSS class (`.btn`, `.card`, `.alert`, …)
plus a Blade stub, with Alpine.js for interactivity.

## Repository layout

- `index.json` — registry manifest (shadcn registry schema). `components[]` each have `name`, `type`,
  `dependencies`, `registryDependencies`, and `files[]` (`path`, `type`, `target`).
- `stubs/ui/*.blade.php` — 180 Blade component stubs.
- `stubs/ui/*.css` — per-component CSS (Tier ②). One file per slug.
- `stubs/tokens.css` — design tokens (Tier ①).
- `stubs/semantic-base.css` — full monolith bundle (Tier ③), generated by `scripts/split-css.php --rebundle`.
- `stubs/dark.css` — dark-mode overrides (must stay in parity with the monolith's `@layer utilities`).
- `scripts/split-css.php` — splits the monolith into per-component files, or reverse-merges (`--rebundle`)
  per-component files back into the monolith. Run from repo root: `php scripts/split-css.php --rebundle`.

## Rules for edits

- When adding/renaming a component, update BOTH `index.json` and the matching `stubs/ui/*.blade.php` + `.css`.
- Keep `stubs/dark.css` in parity with `stubs/semantic-base.css` (the monolith's dark utilities).
- After editing per-component CSS, regenerate the monolith: `php scripts/split-css.php --rebundle`.
- Validate JSON: `php -l` does not apply; use `json_validate(file_get_contents('index.json'))` or
  `jq empty index.json`.
- Do NOT invent semantic class names — verify against `stubs/ui/<slug>.css`.

## Publishing

- Real repo URLs are already set in `index.json` (`homepage`) and `README.md` (registry URL).
- Push to `main`; the raw `index.json` on GitHub is the live registry endpoint.
